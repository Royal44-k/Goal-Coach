## 环境

通俗概念：固定工具版本让每台机器用同一套规则安装和检查代码。项目要求 Node.js 24.20.0、pnpm 11.19.0；TypeScript 命令行使用 7.0.2，`typescript` compatibility 外层包为 6.0.2，其锁文件中的内部 API 版本是 6.0.3，这三个数字不能混为一谈。

- 精确源码：`package.json`、`.node-version`（精确 Node 版本；`package.json` 的 engines 范围为 24.20.x）
- 测试命令：`pnpm typecheck`
- 预期输出：命令退出码为 0，没有 TypeScript 错误。
- 常见错误：用另一个 Node 版本重建原生 SQLite 依赖，或为了安装方便修改锁文件和供应链保护。
- 理解问题：为什么“我机器上能运行”仍不足以替代固定 Node、pnpm 和锁文件？
- 可选自查：未评定，不阻塞软件验收。

- 理解问题：一个进行中的目标为什么可以同时处于 `reviewing`，而 `plan_review` 为什么不能直接进入 `completed`？

## 计划引擎

通俗概念：下一行动和重排信号由纯函数计算。同样的正式任务、签到和显式时间总会得到同样结果；模型不决定进度百分比、依赖关系或哪项任务已经逾期。日历日期按传入时间的固定偏移解释到当天末尾，建议切片限制在 5～30 分钟。

- 精确源码：`src/core/planning/next-action.ts`
- 测试命令：`pnpm test src/core/planning/next-action.test.ts --reporter=verbose`
- 预期输出：依赖过滤、逾期优先和建议切片案例全部通过，测试退出码为 0。
- 常见错误：让纯函数读取系统时钟，或从自由文本猜测正式阻碍与完成状态。
- 理解问题：有一项已完成前置任务、一项逾期 15 分钟任务和一项仍阻塞的 10 分钟任务时，为什么应选逾期任务？

## 数据库

通俗概念：SQLite 只负责保存字节和事务，Repository 才负责 owner 范围、Zod 校验与乐观版本。每次写入都携带读到的 `version`；若别处已经更新，旧写入返回 `VERSION_CONFLICT`，不会静默覆盖。迁移可以重复运行，但已提交的旧迁移不能直接改写。

- 精确源码：`src/server/db/migrate.ts`
- 测试命令：`pnpm test src/server/db/db.test.ts --reporter=verbose`
- 预期输出：迁移、外键、WAL、重复迁移和关闭连接案例通过，测试退出码为 0。
- 常见错误：把“SQLite 能读出来”当成业务数据有效，或用删除现有数据库代替修复迁移问题。
- 理解问题：两个页面都读到版本 1，其中一个保存成版本 2 后，为什么另一个不能继续覆盖？
- 可选自查：未评定，不阻塞软件验收；不得为练习读取、移动或清除用户现有数据库。

## 工具权限

通俗概念：Permission Gate 判断“这次操作能不能发生”；`ApprovalGrant` 把 owner、subject、工具名、SHA-256 内容摘要和 15 分钟期限绑定为一次性批准。`operationId` 解决的是“同一个操作是否已经发生”：相同请求重试返回原结果，换参数复用同一 ID 会被拒绝。批准与幂等不能互相替代。

- 精确源码：`src/server/agent/permission-gate.ts`
- 测试命令：`pnpm test src/server/agent/tool-registry.test.ts src/server/agent/permission-gate.test.ts src/server/security/approval-service.test.ts --reporter=verbose`
- 预期输出：结构性/破坏性工具不出现在模型定义中，无批准调用、复用/变更/过期凭证均被拒绝，测试退出码为 0。
- 常见错误：认为参数格式正确就等于用户批准，或把一次成功 operation replay 误称为重复消费 ApprovalGrant。
- 理解问题：为什么网络中断后的同一 `operationId` 可以安全查询结果，但一个新的删除操作仍必须重新确认？
- 可选自查：未评定，不阻塞软件验收。

## 模型循环

通俗概念：一次用户输入最多触发 4 次模型调用、3 次工具调用和 1 次参数修复。模型提出工具调用后，服务端校验并执行允许的工具，再把同一调用 ID 的结果临时送回模型；协议消息和隐藏推理不写入可见对话。上下文包含当前目标、当前计划摘要及任务、最小偏好、一条对话摘要、最多六条最近可见消息和当前允许的工具定义；还提供最多十条相关有效反馈（每条备注最多 1000 个 Unicode 码点），以及确定性的重规划原因和最新相关可用时间。反馈经过当前目标、所有者、撤销状态和计划沿袭/执行重置规则筛选。撤销反馈时会建立对话分界；分界前可能提到旧反馈的消息和摘要仍保留为历史与导出，但不会再次送入后续模型上下文。

- 精确源码：`src/server/agent/orchestrator.ts`、`src/server/agent/context-builder.ts`
- 测试命令：`pnpm test src/server/agent/orchestrator.test.ts -t "queued function calling" --reporter=verbose`
- 预期输出：用户消息→模型工具请求→本地工具结果→最终回复只执行一次并通过，测试退出码为 0。
- 常见错误：把模型提出调用当成写入已经成功，或在结果未知时自动生成新 operationId 重试。
- 理解问题：工具返回后为什么还需要第二次模型调用，哪些消息会保存，哪些只在本轮内存在？
- 可选自查：未评定，不阻塞软件验收。

反馈筛选与请求上限见 `src/server/agent/context-builder.ts` 和 `src/server/services/feedback-context.test.ts`。当前按你的选择保留 Qwen 接口但不启用；这里说明的是代码中的模型协议，不表示已经调用或验证了真实模型。

Qwen SDK 单次请求超时是 45 秒且 SDK 自动重试关闭；超时是否允许再试由 Orchestrator 根据本轮是否已提交领域修改决定。每日预算在每次发送前检查，已知供应商用量返回后才记录；没有用量的超时不能被说成零 Token。删除单个目标保留用量凭据；local 全部清除重建设置并重置本机用量，invite 只清当前账号业务内容并保留账号、安全记录和日配额。这些守卫均不构成供应商账单上限。

## 界面

通俗概念：浏览器只通过严格 HTTP API 读取和修改数据。非 GET 请求必须来自配置的可信 Origin；正文、路径和查询都经过 Zod。local 的 owner 取服务端固定本机身份，invite 则从已认证会话解析；浏览器多传 `ownerId` 会被严格拒绝。已收到的安全错误和“结果未知”不同：前者可刷新后给出明确恢复入口，后者只能重读状态或用同一请求查询。

- 精确源码：`src/components/workspace/goal-workspace.tsx`
- 测试命令：`pnpm test src/components/workspace/goal-workspace.test.tsx --reporter=verbose`
- 预期输出：正式状态刷新、草案批准、执行、恢复和手动操作组件案例通过，测试退出码为 0。
- 常见错误：页面重新挂载时自动调用模型，或把网络断开解释为“服务器没有写入”。
- 理解问题：为什么收到 504 安全信封可以显示模型超时，而连接断开时必须先查询同一请求或重新读取正式状态？
- 可选自查：未评定，不阻塞软件验收。

当前界面已经覆盖创建、契约/计划确认、任务执行、阻碍建议、重规划、暂停/恢复、最近一次任务修改或反馈的统一撤销、完成复盘、导出和清除。任务撤销恢复状态与实际用时；反馈撤销保留历史标记并排除当前分析。旧库记录时间完全相同时按任务修改在前、反馈在后建立顺序，因此先撤销反馈；旧库无法证明的跨表先后不会被伪造。历史建议和复盘不会被改写成新的模型结论，输入变化时显示为历史，之后只有明确请求才会依据有效反馈重新生成。离线或模型失败时，正式目标和已有任务仍可手动管理。初次计划还没有任务时不能声称存在“手动编辑任务”控件；用户可保留已保存目标、重试模型，或回到当前阶段实际可用的目标控件。

通俗概念：mock 评测证明 30 个固定案例的程序行为可重复，不证明真实模型质量。真实 Qwen 评测需要单独授权；30 案例在每案最多 4 次模型调用的协议下，理论最大为 120 次供应商调用，但本机没有严格逐案例 Token 或账单上限。人工评分必须来自与结果文件逐案匹配的真实评审，不能由机器补写。

- 精确源码：`evals/run.ts`
- 测试命令：`pnpm eval`

- 理解问题：mock、真实模型和人工评分分别能证明什么，为什么三者不能互相替代？
- 可选自查：未评定，不阻塞软件验收。

本机交付提供只读安全预检、固定 `127.0.0.1` 的前台生产启动和带 SHA-256 清单的白名单源码包；使用方法见[源码交付说明](../delivery/README.md)。设置页仍只允许人工编辑偏好时间段和有效策略；任务粒度、估时偏差与常见阻碍由有效执行记录重新推导。生产构建、持久化、导出/清除、无泄漏检查和全新 Windows 安装是不同证据。自动化、真实模型质量、人类评审和干净环境不能互相替代；个人操作仅为可选学习记录，不是软件交付门槛。本机历史验收见[原记录](../verification/local-mvp-acceptance.md)；0.2.0 邀请功能已实现，但真实 Qwen、Linux 容器、DNS/TLS、公网部署/恢复以及全新 Windows 安装仍未验证，不能把代码交付说成已经上线。

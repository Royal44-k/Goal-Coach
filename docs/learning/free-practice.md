# 免费实操卡：从已批准计划到完成复盘

这是一份可选的本机有限 mock 免费练习卡，不是需要你完成的测试任务。软件验证由 Codex 使用隔离数据执行；你可以只阅读，不必点击或提交任何内容。若选择练习，以下操作在浏览器页面完成，不是在 Codex 聊天里完成，也不会调用付费模型。若练习服务已经打开，直接回到现有目标，不要另开服务器或重复创建目标；安装与首次进入只参考[项目 README](../../README.md)。

有限 mock 只保证下面两句示例输入，不代表它能理解任意自然语言：

```text
四周内学会 TypeScript，每天一小时，做一个待办网页
待办网页可以新增、勾选完成和删除任务，刷新后仍保留记录。
```

从页面已经显示“当前已批准计划”开始即可。这里说的“完成真实工作”和“只训练界面流程”只是两种学习方式，不是应用里的模式开关，也不是 mock/live 设置；若只练流程，所有说明和证据都明确写“流程练习：未验证真实 TypeScript 成果”，不要编造代码、耗时或完成事实。自动化通过、走完界面和真正学会 TypeScript 是三件不同的事。

## 1. 先记录一次阻碍

1. 点击“报告阻碍”，在“哪里卡住了？”中选择最接近的真实类别，例如“时间不足”或“不知道如何开始”。
2. “补充说明（选填）”写真实情况；流程训练则用“流程练习：……”开头。
3. 点击“请教练帮我分析”。先保存的是阻碍记录；页面随后显示“最小下一步”。这条建议本身不会改写正式计划。
4. 若恢复面板要求确认，可选择“继续请求教练分析”，也可选择“仅保留已保存的阻碍记录”。

按钮和六类阻碍来自[阻碍表单](../../src/components/blockers/blocker-dialog.tsx)，保存后才继续请求建议的顺序来自[目标工作区](../../src/components/workspace/goal-workspace.tsx)。有限 mock 只支持这个 TypeScript 示例目标的按钮触发消息。

## 2. 按依赖顺序执行任务

1. 从第一个可用任务开始，点击“开始：任务名”。有未完成依赖的后续任务会保持不可用。
2. 做完真实工作后填写“实际用时（分钟）”，只接受大于 0 的整数；暂不记录时留空，不填 0。已有数值时，清空输入框并移开焦点会清除该用时记录。这个数字是已经花掉的时间；“每周预算”是每周可投入容量，两者不是同一个数。
3. 实际用时在输入框失去焦点时保存：按 Tab 或点击框外，然后等待保存及正式状态重新读取完成，再继续点“完成”。
4. 点击“完成：任务名”，按该任务要求填写“文字说明”“检查答案”“用户确认”或选择文件，再点击“确认完成并保存证据”。初始有限计划使用“文字说明”。
5. 检查任务状态和“正式进度”的完成数/百分比，再进入下一个依赖已满足的任务。

应用只记录你提交的证据，并不会自动证明内容正确。若以真实成果为学习方式，必须先完成对应工作并按“完成标准”如实写证据；若本次只学习界面流程，只能提交清楚标注的流程训练记录，不能把它说成真实学习成果。应用本身没有这两种学习方式的切换开关。相关控件见[任务列表](../../src/components/tasks/task-board.tsx)、[证据表单](../../src/components/tasks/evidence-dialog.tsx)和[正式进度](../../src/components/workspace/progress-panel.tsx)。

## 3. 可选：观察撤销与历史

出现“撤销上一次修改”时，先看候选标签，再点击按钮。候选是任务修改时会恢复任务状态和实际用时；候选是打卡/阻碍反馈时会标记为“已撤销”，原记录仍留在“反馈历史”，但不再参与当前建议、偏好推导或复盘事实。每次只处理当前目标最近一条支持撤销的记录；页面过期、最近记录已变化或历史计划任务不适用时会要求刷新，不会偷偷跳过它改撤更早记录。完成证据、计划批准和删除不随之撤销。撤销后先核对页面重新读取的正式状态，再决定下一步。详见[撤销提示](../../src/components/tasks/undo-banner.tsx)。

## 4. 可选：审阅一次计划调整

- 只有真实保存的数据触发“计划可能需要调整”时，才点击“请教练评估”；不要为制造信号伪造耗时或成绩。有限 mock 只支持这个按钮提供的固定调整请求，不支持任意聊天指令。
- 也可在确有调整需要时点击“编辑计划任务”，写明真实“修改原因”，生成待审草案。
- 在“比较两版计划”中核对“当前有效”和“待批准”、原因、任务差异与执行重置信息。可选择“继续使用当前计划”“要求修改”或“批准新计划”。未批准前，当前计划仍有效。

批准调整会建立新的计划版本和新的任务 ID，并重映射依赖。语义未改变的执行状态和证据可带来源复制；行动、完成标准、证据要求或相关依赖发生实质变化时可能重置执行状态，因此不要假定所有修改都保留、都可撤销。界面见[重规划审阅](../../src/components/plans/replan-review.tsx)，身份/依赖/证据语义由[计划版本仓储](../../src/server/repositories/plan-repository.ts)实现。

## 5. 完成任务后做复盘

1. 当前计划的全部任务都按依赖顺序完成后（初始示例为三项），正式进度到 100%，页面出现“完成前复盘”。任务全完成不等于目标已完成。
2. 点击“生成目标复盘”。有限 mock 只概括已保存的任务数、实际用时和证据数；刷新不会自动生成。
3. 在“已保存的生成复盘”中对照上方当前执行记录。勾选“确认已核对当前执行数据，并理解生成复盘可能早于后续修改”。
4. 最后点击“确认完成目标（目标 N）”。只有这一步才把目标正式标为完成。

具体门槛和按钮见[目标复盘](../../src/components/review/goal-review.tsx)。完成状态来自用户确认，不来自进度条自行推断。

## 6. 可选导出，然后保留记录

从侧栏进入“设置与数据”，在“导出或永久清除”中点击“导出 JSON”即可保存公开目标数据。当前导出为 `schemaVersion: 2`，会保留反馈的 `withdrawnAt` 状态、历史对话摘要和对话消息，因此它是历史备份，不只是当前有效分析输入。这个练习不要求删除目标或清除数据库；保留记录、关闭页面，之后回到同一目标继续即可。导出范围见[数据控件](../../src/components/settings/data-controls.tsx)。

刷新或离开前，先提交或取消仍在编辑的输入，并等待保存/重新读取结束。若普通修改显示结果未知，只使用当前恢复面板的“查询本次修改结果”重放同一请求，或“重新读取正式状态”；若教练请求显示结果未知，只使用“查询本次教练结果”重放同一请求，或“重新读取目标状态”。以页面当前显示的恢复面板为准，在结果对账完成前不要发起新的写入。模型离线或超时时，已有批准计划和任务仍可使用手动控件；尚未生成初始计划时没有任务编辑器，有限 mock 也不支持任意对话。

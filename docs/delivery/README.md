## 安装、迁移与启动

在源码目录中依次完成 README 的依赖安装和 `.env.local` 配置。不要覆盖已经存在的 `.env.local`。确认要使用哪一份 SQLite 数据库后再迁移；继续已有练习时，应显式沿用原来的绝对路径：

```powershell
$env:DATABASE_PATH = "D:\明确的目录\goal-coach.db"
pnpm db:migrate
pnpm build
pnpm local:check
pnpm local:start
```

若不设置 `DATABASE_PATH`，默认使用源码目录下的 `data/goal-coach.db`；这可能是一份新库。不要因为新库为空就判断原数据丢失。`local:check` 是只读预检：它核对精确 Node 版本、本地 Next/SQLite 依赖、`.next/BUILD_ID` 和 3000 端口，不读取 `.env` 内容、不安装依赖、不构建，也不结束任何监听器。缺少构建或端口被占用时返回非零并给出中文诊断。

`local:start` 只有在同样的预检全部通过后，才调用当前源码目录已安装的 Next CLI，以 `start --hostname 127.0.0.1 --port 3000` 在前台运行。它继承当前环境，显式 `DATABASE_PATH` 会保持不变；Next 仍按自身规则加载现有环境文件。启动器不会复制或覆盖配置，也不会强制改变数据库中保存的模型选择。按 `Ctrl+C` 停止它拥有的子进程；它不会结束来源不明的端口监听器。

## SQLite 备份与恢复

提供 `pnpm db:backup -- <新路径>`，从显式环境变量 `DATABASE_PATH` 使用 SQLite backup API 生成经完整性和外键校验的备份，可以包含正在使用的 WAL 已提交数据。目标必须不存在；不要在服务写入时普通复制主 `.db`。

恢复必须停止应用并保留当前库，运行 `pnpm db:restore -- <备份> <全新数据库路径>`，不能覆盖旧文件或混入其他 WAL/SHM。完整命令、卷权限、账号恢复和不可降级迁移的回滚边界见[运维手册](../deployment/operations.md)。

## 统一撤销与历史

每个目标只显示最近一次支持撤销的候选：

- 任务修改撤销会恢复原任务状态和实际分钟数，完成证据继续作为历史保留。
- 打卡/阻碍反馈撤销会写入 `withdrawnAt`，不删除原文；它仍显示在反馈历史和导出中，但不参与当前建议、三个推导偏好信号或复盘事实。
- 设置页可人工编辑的偏好仍只有“偏好时间段”和“有效策略”；任务粒度、估时偏差、常见阻碍会从当前有效记录重新计算。
- 若页面候选已过期、最近记录发生变化或记录已不适用，系统拒绝并要求刷新，不会跳过它去撤销更早记录。重复同一请求只返回同一结果。
- 旧库迁移遇到完全相同时间时，按任务修改在前、反馈在后建立历史顺序，所以反馈先被撤销；旧数据无法证明的跨表先后不会被伪造。
- 已生成的建议或复盘不会被重写成新的模型结论。相关反馈撤销后，它们保留为历史或离开当前建议；后续只有明确请求才按有效记录重新生成。

JSON 导出使用 `schemaVersion: 2`。它保留全部反馈及 `withdrawnAt`、`conversationMessages` 和历史 `conversationSummaries`，因此导出是历史备份，不等同于后续模型的当前有效上下文。版本 1 导出没有这些完整字段，消费方应按版本区分。

## 源码包

维护者可运行：

```powershell
pnpm package:source
```

命令在 `dist/` 中创建新的 `<package>-source-v<version>` 目录，并生成 `manifest.json`；清单按稳定路径顺序记录每个复制文件的字节数和 SHA-256。目标目录已存在时拒绝覆盖，白名单目录内发现符号链接时在创建目标前拒绝。允许内容限于源码、迁移、必要配置、锁文件、测试和面向交付的文档；明确排除 `.git`、`node_modules`、`.next`、其他 `dist`、所有非示例 `.env`、数据库、用户导出、日志、测试结果、评测结果和内部工作笔记。

源码包没有自动上传或自动安装行为。接收方必须自行验证清单、安装锁定依赖、配置、迁移和构建；不能把它描述成无需安装的可执行发布物。当前机器上的测试也不能证明全新 Windows 环境已安装成功。

## 模型与外部边界

DeepSeek 软件适配及 Qwen 入口均保留。当前电脑的 DeepSeek 配置和真实合成场景调用已记录在最新全量验收报告；配置、模型机械闭环和方案内容质量分开判定，不能从旧版“未调用”或某一次成功推断最终结论。选择 mock 时仅运行有限、确定性的预设流程，不能理解任意自然语言；选择真实提供方但缺少其配置会明确报错，不静默伪装为真实模型。手动目标、已有批准计划、任务执行、统一撤销、导出和清除不依赖外部模型，但 PWA 断网时只能显示静态说明页，私人目标与账号操作仍需连回服务器。

本次没有交付公网访问。邀请功能在应用层已实现，但目标 Linux 环境仍须验收镜像、卷权限、Caddy/HTTPS 和备份恢复；不要直接暴露本机 Next 服务。

旧版本实际验证结果见[2026-09-18 交付验证记录](verification-2026-09-18.md)，仅代表当日版本。0.2.0、0.2.1 历史源码包不覆盖；0.2.2 必须在本轮最终源码与文档冻结后另行打包、核对清单和 ZIP，实际生成情况以全量验收记录和包旁校验文件为准。

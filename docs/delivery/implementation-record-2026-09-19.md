## 执行期间作出的决定

按作出顺序记录；被后续决定替代的方案仍保留，避免把探索过程误写为最终配置。

1. 延续用户已选择的子 Agent 驱动开发，不在每个常规任务之间重复请求批准。依据是用户要求连续负责到底。若理解有偏差，需要调整偏好；不因此获得发布、购买或操作真实数据的授权。
2. 封闭邀请版采用 Node 标准密码散列与 SQLite 不透明会话，不接入第三方身份服务。好处是无需另申请身份平台凭据；代价是未来公开运营可能需要身份迁移和独立安全审计。
3. 本版只做不联网的 Qwen 配置检查，真实验证留给未来明确授权的受控评测。避免新增另一条未受控付费路径；代价是首次真实验证不能靠当前页面一键完成。
4. 起初计划使用单独构建目录，防止影响旧练习服务。代价是增加构建目录配置及打包排除规则；该方案后来被替代，未作为生产设置交付。
5. 在确认旧端口和进程已不存在后，一度改为普通构建目录。风险是未检测到返回的服务，因此要求构建前再检查；此决定又被下一步私人配置隔离决定替代。
6. 任务阶段只用夹具验证打包；真实、拒绝覆盖的 `v0.2.0` 源码包在指南和最终审查后生成。这样包中包含完整交付文件；代价是完整包的反馈较晚，但打包程序已先测试。
7. 每账号每日新 Agent 回合配置限定为整数 1–1000，默认 50。避免邀请试用时误配过大额度；代价是以后更高量使用需要明确修改策略，而不是仅改环境变量。
8. 仅检查到 `.env.local` 存在后，改为无私人配置和数据的白名单源码副本进行构建、浏览器验收。原文件不读取、不移动；复用依赖时允许副本专用 Turbopack 根目录调整并披露。代价是夹具设置更复杂，必须说明验证环境与生产配置的这个差异。
9. 邀请模式清空业务数据后，仍保留不含目标/对话内容的账号用量和尝试去重记录；清空后返回的已知模型用量也计入。本机模式维持原有重置行为。这样不能靠清空绕过共享额度；代价是增加少量持续存储，并需明确隐私说明。
10. 部署阶段的源码白名单提前纳入下一阶段的邀请浏览器测试与配置，避免交付包缺少指南中的验收入口。代价只是多带少量测试源文件，不扩大私人配置或运行数据的允许范围。
11. 实际 Edge 验收发现账号输入框的 HTML 正则解析错误后，在验收阶段批准最小转义修复，不改服务端账号规则。若处理不当可能造成前后端校验不一致，因此加入浏览器合法/非法账号名回归。

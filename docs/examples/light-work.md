# 轻工作场景：建立会议决议与待办目录

## 场景与边界

适用对象：想把会议记录转成可追踪行动的小团队成员。合成目标是在 2026-10-11 前，从合成会议样本整理出决议、负责人和待办目录，能检索并逐条验证；每周可用 180 分钟。

本案例 2026-09-27 使用 `deepseek-flash` 完成 **7 次真实 API 请求**。没有上传真实公司会议记录，也没有真实团队成员或客户成果。Goal Coach 指导人完成整理，不会在本例中自动读取外部会议系统。

证据：[结构化摘录](evidence/light-work.json)。公开摘录去掉随机标识、原始内部推理和完整日志，保留可核对的计划与断言。

## 操作链路

可按下面的场景表达开始，日期改成未来两周内的真实期限：

> 我想在两周内把几份会议记录整理成可检索的决议和待办目录，包含负责人，能逐条验证没有遗漏；每周能花三小时。先用虚构样本演练。

这是复现提示，不是原对话逐字稿。关键步骤是：目标契约草案 → 用户确认 → 5 项计划草案 → 用户确认 → 合成执行证据 → 撤销/恢复检查 → 阻碍 → 用户明确选择时间 → 重排草案 → 确认 → 复盘、完成与导出。

在第一项完成后，第二项“提取决议与负责人”遇阻，每周时间先变成 90 分钟。成功链路随后由合成用户**明确恢复到 180 分钟**，并非模型擅自增加可用时间，也不证明 90 分钟条件下能够完成。

| 原计划 | 分钟 | 确认后的重排 | 分钟 |
| --- | ---: | --- | ---: |
| 确认合成会议样本并定义目录结构 | 40 | 保留，已完成 | 40 |
| 从样本中提取决议与负责人 | 40 | 起步：只填第 1 份样本的一条决议与负责人 | 20 |
| — | — | 按起步模板补齐样本中的决议与负责人 | 25 |
| 补全待办项字段 | 40 | 保留 | 40 |
| 设置可检索方式并自测查找 | 30 | 保留 | 30 |
| 用合成样本逐条验证并留记录 | 30 | 保留 | 30 |

总估时从 180 增至 185 分钟，未完成部分由 140 增至 145 分钟；验收时剩余容量为 366 分钟。没有通过省略样本或减少验证来制造“效率提升”。第一条起步记录进入正式目录，后续补齐其余内容并统一验证。

## 能说明什么

拆小的价值是降低启动门槛、明确当前该填哪一条，以及怎样把这条记录继续扩展为完整交付。已完成任务与证据保留，正式计划必须经用户确认，最终可导出。

不能说明：真实公司采用率、节省多少人力、全部模型回答都准确，或自动接入会议/日历/办公系统。合成实际用时 160 分钟不是效率数据。请勿把真实商业机密直接放入模型，先确认授权、供应商说明及组织要求。

## 复现

按[使用教程](../guides/user-guide.zh-CN.md)操作，先用虚构样本。任务完成要留下真实目录条目或可核对的说明；不要把验收用的“完成”文字当真实工作证据。

如需运行同类自动化合成验收，在已配置 Key 且接受费用后，于项目根目录执行：

```powershell
node --import tsx evals/lifecycle-run.ts --provider=deepseek --allow-live --scenario=light_work --replan-mode=confirm-more-time
```

这是恢复原时间后的成功分支；模型输出有随机性，不保证逐字复现。该历史案例输入 **43,526**、输出 **3,766** token，共 7 次请求。一次请求上限不是账户费用上限，失败也可能计费，不自动无限重跑。

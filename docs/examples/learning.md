# 学习场景：四周完成一个 TypeScript 待办网页

## 场景与边界

适用对象：有学习意愿但不知道今天从哪里开始的初学者。合成目标是到 2026-10-25 完成可运行的 TypeScript 待办网页，能新增、完成、删除任务，并在浏览器刷新后保留数据；每周可用 240 分钟。这里的日期是历史验收日期，自己使用时改成真实未来期限。

本案例 2026-09-27 使用 `deepseek-flash` 完成 **7 次真实 API 请求**。目标输入与所有完成证据为合成数据。Goal Coach 负责规划和跟进，不会自动替用户写出待办网页。

证据：[结构化摘录](evidence/learning.json)。该文件保留源产物 SHA-256，可由持有私下原件的维护者核对；公开仓库不附原始日志。

## 从目标到行动

可以输入这样的目标：

> 我想在四周内做一个 TypeScript 待办网页，支持新增、完成、删除和刷新保留数据。每周能投入四小时，希望任务具体到能直接开始。

这段文字是便于读者复现的场景表达，不冒充原始对话逐字稿。验收器实际核对的是 JSON 中的契约、工具结果和状态。

| 阶段 | 实际检查 |
| --- | --- |
| 澄清与契约 | 明确成果、期限、时间；先形成草案，由可信用户操作确认 |
| 初始计划 | 5 项任务，总估时 750 分钟；确认后才成为正式计划 |
| 执行 | 写入合成完成证据；状态、撤销及恢复后读回一致 |
| 阻碍 | 第一项已完成，第二项遇阻；每周可用时间先减半到 120 分钟 |
| 明确选择 | 合成用户主动恢复到 240 分钟，才继续后续重排 |
| 重排确认 | 保留已完成项和证据，将骨架工作拆成更小的开工步骤；审阅后批准 |
| 复盘与完成 | 核对记录、完成状态和导出；不凭模型一句话标记成功 |

## 价值与不足

可见价值是把“卡在做页面”变成一个明确的 20 分钟起步动作，同时保留后续交付与验证工作。这只是可操作性证据，不是提效比例。测试记录中的 165 分钟合成实际用时不能用于宣传效率。

独立内容评审通过核心交付链，但记录了复盘措辞问题：文字没有完整提及已有的自测证据，且对已保存复盘又询问是否保存。因此仍需以状态和证据为准，不能盲信总结文字。

## 如何亲自复现

1. 按启动指南进入应用，选择 mock 熟悉确认、任务和撤销；mock 不能理解任意自然语言。
2. 私下配置 DeepSeek，重启服务，在设置页同意数据说明。使用上面的目标并改成真实日期、真实可用时间。
3. 审阅契约和计划；自己实际完成任务后填写真实证据。遇阻时描述具体问题，审阅重排差异后确认。
4. 若只是重现自动化合成验收，确认会收费后，在仓库根目录运行下面命令；它不替你完成真实学习任务。

```powershell
node --import tsx evals/lifecycle-run.ts --provider=deepseek --allow-live --scenario=learning --replan-mode=confirm-more-time
```

此命令是明确增加可用时间分支，不代表时间减半分支通过。当前日期、模型输出或余额变化可能导致失败，保留失败记录，不无限重试。该历史案例用量为输入 **43,869**、输出 **4,168** token；不是本次复现的费用承诺，也不是人民币硬上限。

# 邀请试用与 Qwen 接入准备设计

日期：2026-09-19。基线：67af445。本设计承接用户批准的顺序：Qwen 准备 → 邀请登录/隔离/额度 → 部署 → 自动验收 → 完整指南。用户要求连续执行，密钥暂不申请，常规规格/计划由执行方写入并检查，不重复暂停请求批准。

## 目标与范围

让当前本机应用具备小范围邀请试用的软件能力，交付可重复部署的源码、配置、维护脚本和中文操作指南。保留本机无登录模式，不改变现有练习数据。Qwen 配置保持空白；不得调用真实模型、购买云资源、发布公网服务或将用户数据库上传。实际云主机/DNS/TLS、真实 Qwen 和 Linux 容器验收若缺少环境必须明确未验证，不以本机测试代替。

## 全局约束

- Node.js 24.20.x、pnpm 11.19.x，现有依赖锁定；不升级运行时或框架。
- 不读取或输出 .env.local、API Key、真实用户数据库内容；验证使用独立临时数据库。
- 不出现“本机 · 私密 · 可撤销”等展示样机式标语；必要的状态、隐私与错误提示保留。
- 模型默认 mock，DASHSCOPE_API_KEY 和 DASHSCOPE_BASE_URL 保持空白；无真实模型网络请求。
- 本机模式与邀请模式明确隔离，公网部署只允许邀请模式，数据存储为单实例持久化 SQLite。
- 每个任务遵循测试先行，审查后推进；不合并、推送或对外发布。

## 方案选择

采用单台 Linux 云主机 + Docker Compose + Caddy HTTPS + 一个 Next.js Node 进程 + SQLite 数据卷。相较托管前端加远程数据库，它沿用现有存储；相较直接暴露本机端口，它可以加入认证、访问控制和运维。当前不引入 Redis、集群或付费身份服务。认证使用标准 Node crypto scrypt 与随机不透明数据库会话，不自行设计加密算法；仅用于封闭邀请试用，日后公开服务应评估成熟身份服务与独立安全审计。

## A. Qwen 准备

保留两个既定快照模型。请求显式关闭思考并限制单次输出为 2048 tokens，服务端环境可在 128–8192 内调整。保持普通文本与工具调用协议，不强制对自然语言回复启用 JSON 模式。区分鉴权/权限、模型或参数不可用、上游限流、连接失败、超时；不输出供应商原始错误、请求正文或密钥。

设置页面提供只读配置检查（不联网）：显示 Key/地址是否齐备、当前实际模式、固定模型、尚未真实验证。可以提供显式的真实连接测试入口，但默认不执行，用户先确认会产生模型请求；只发送固定无业务文本，不写入目标。此功能必须有服务端鉴权、配置检查、单次上限与调用限流，不在页面加载或保存时触发。没有 Key 时展示可操作的配置说明。

## B. 邀请账号与身份

APP_MODE=local|invite（默认 local），APP_ORIGIN 默认 http://127.0.0.1:3000；local 仅允许这个回环主机（允许显式本机端口），invite 的正式地址必须 HTTPS（仅回环地址允许 HTTP 用于自动测试）。不得依赖客户端提交的 ownerId、角色、Host 或 X-Forwarded-* 确定身份/可信来源。

新增用户、邀请、会话和持久化限流表，迁移只能增加表，不移动既有业务数据。所有新账号生成独立 UUID，不继承 LOCAL_OWNER_ID。

- 邀请：随机 32 字节凭证，只存 SHA-256 摘要；有效期 72 小时、一次使用；注册事务原子消费，失败不消费。
- 注册：邀请码 + 唯一规范化账号名（3–32 ASCII 字母/数字/下划线/短横线，转小写）+ 密码（12–128 字符，不 trim 密码）；不开放无邀请码注册。
- 密码：随机独立盐、异步 scrypt，N=32768,r=8,p=3,maxmem=64MiB，恒时比较；数据库不含明文密码。
- 会话：登录成功新建随机 32 字节令牌，仅保存摘要，7 天绝对有效期；HttpOnly、SameSite=Lax、Path=/，HTTPS 下 Secure；注销立即删除会话。禁用用户与密码重置立即撤销其所有会话。
- 管理：通过服务器 CLI 创建首个管理员邀请（已有管理员或未消费管理员邀请时拒绝重复引导）；管理员在网页创建普通邀请、列出/禁用用户及撤销未使用邀请。不允许管理员通过这些接口查看别人的业务数据。密码忘记时管理员 CLI 从 stdin 接收新密码、撤销会话，指南说明无邮件找回。
- 限流：登录/注册在昂贵密码运算前以数据库全局限流和账号摘要限流控制，不能信任可伪造代理 IP；默认每分钟全局 30 次、每个账号 5 次。无效用户名不绕过全局限流。限流记录按过期回收。

## C. 全入口隔离与费用边界

统一请求身份解析：local 返回固定本机身份；invite 从 Cookie 查数据库会话。所有业务 API，包括 GET/export、设置、审批、撤销、删除和 Agent，先解析身份再调用服务。未登录 401，跨用户 ID 返回 404/权限错误且不返回任何他人数据。移除 AgentTurnStore 的“只允许本机用户”限制，保留具体目标归属与事务校验。

邀请模式中 provider、fallback 和每用户模型额度来自服务器环境，普通用户与管理员都不能通过个人设置提高服务器额度。隐私同意和偏好仍按用户保存。现有 settings API 保持字段契约，但云模式下敏感设置只读、服务端也拒绝修改；只有运维修改环境并重启才改变共享模型配置。

每用户最多一个活跃 Agent 回合，全实例最多两个；每用户每天最多 50 个新回合（可配置但有合理上限）。重放同一 operationId 不重复收费计数，超限拒绝不产生供应商请求；在持久化记录处落实每日准入，并以单实例并发闸门约束执行。另保留现有用户 token 统计上限；明确它不是供应商账单硬上限，超时未知用量/思考等仍需供应商侧预算监控。

写请求必须精确匹配 APP_ORIGIN，Cookie 不是 CSRF 的替代；JSON 请求限长（256 KiB），拒绝超限正文，健康检查不返回数据库路径/模型Key/用户数。所有含身份/业务数据响应 no-store，不记录请求正文和 Cookie。页面未登录时引导登录，API 鉴权才是真正安全边界。

## D. 部署与运维

Docker 在 Linux 镜像内安装锁定依赖并构建 native SQLite；不得复制 Windows node_modules。非 root 单实例运行，仅 Caddy 暴露 80/443，应用端口只在 Compose 网络内。APP_MODE 在 compose 强制为 invite，APP_ORIGIN 从所配域名派生；模型默认 mock。配置文件不包含密钥，Docker 上下文排除 .env*（仅允许显式样例）、data、dist、.git、测试产物。

健康接口检查本地配置/数据库连通性，不调用 Qwen。备份使用 SQLite backup API 得到一致快照，验证 integrity_check 和 foreign_key_check。恢复离线执行，拒绝覆盖现有数据库；推荐先备份旧卷、恢复到新卷并切换，不能直接 cp 正在写入的 WAL 数据库。提供容器内可运行的管理/备份入口和健康检查。

## E. 验收与指南

自动测试：Qwen 假传输请求参数与错误脱敏；邀请码重复/过期/并发消费；密码和会话/注销/禁用；匿名拒绝；两用户目标、Agent、审批、导出、清空隔离；Origin 与限流；旧版业务回归。浏览器覆盖邀请注册→登录→创建目标→注销→另一用户隔离，以及无 Key 配置状态。数据库恢复在临时目录实测。完整 lint/typecheck/unit/build、现有免费评测与本机 E2E；容器环境不可用时明确记录未执行 Docker 构建，提供运行命令，不伪造结果。

中文指南顺序：当前交付边界 → 本机继续使用 → 云资源/域名准备 → 配置与构建 → 引导管理员 → 邀请朋友 → 备份/恢复/升级回滚 → 将来接入 Qwen → 上线验收清单 → 常见错误与费用/安全边界。所有命令匹配实际脚本；示例值清晰标记，严禁给用户看似可用的假公网网址或通用密码。

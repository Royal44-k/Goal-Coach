# DeepSeek live acceptance and Alibaba Cloud Hong Kong deployment: official-source notes

Checked 2026-09-24 against first-party documentation. These are source facts and repo-specific implications, not evidence of a live account, purchased ECS, successful API call, or Linux deployment. Recheck console availability and prices immediately before purchase.

## DeepSeek API

- DeepSeek's [first API call guide](https://api-docs.deepseek.com/) directs users to apply for an API key on the [DeepSeek API Platform](https://platform.deepseek.com/api_keys) and gives the OpenAI-compatible base URL `https://api.deepseek.com`. The [API reference](https://api-docs.deepseek.com/api/deepseek-api/) specifies Bearer authentication. Create a key in the owner's account, supply it only through the server's private configuration, and use an actual model request to establish live acceptance; merely saving a key cannot prove billing or connectivity.
- The [current model and pricing page](https://api-docs.deepseek.com/quick_start/pricing/) and [Chat Completions reference](https://api-docs.deepseek.com/api/create-chat-completion/) list both `deepseek-flash` and `deepseek-v4-pro`. The latter reference supports `thinking: {type: "disabled"}`, `max_tokens`, and function tool calls, matching the repository's intended non-thinking chat workflow. `deepseek-flash` routes to V4.1 Flash; V4 Pro remains separately listed as of this check. Model availability can change.
- Published USD prices **per 1 million tokens** at this check: Flash input cache hit $0.003 off-peak / $0.006 peak, input cache miss $0.15 / $0.30, output $0.60 / $1.20; V4 Pro input cache hit $0.022 / $0.044, input cache miss $0.66 / $1.32, output $1.98 / $3.96. DeepSeek says peak is 01:00–04:00 and 06:00–10:00 UTC Monday–Friday excluding Chinese public holidays, and reserves the right to change prices. A cache hit is a distinct billing category, **not** a safe assumption for every input. These rates do not imply a fixed monthly bill. [DeepSeek pricing](https://api-docs.deepseek.com/quick_start/pricing/).

## ECS purchase and access

- In ECS **Custom Launch**, select region **China (Hong Kong)**, a regular **x86_64/amd64** instance, Ubuntu **24.04 LTS** public image, a system disk, and **Assign Public IPv4 Address** for direct public web hosting. Alibaba lists separate `x64` and `arm64` Ubuntu 24.04 images. The proposed **2 vCPU / 4 GB RAM / 40 GB SSD** is an engineering starting point for this small app, not an Alibaba minimum, live stock claim, performance guarantee, or price quote. Confirm the selected instance family's image compatibility and the final order summary. [ECS Custom Launch](https://www.alibabacloud.com/help/en/ecs/user-guide/create-an-instance-by-using-the-wizard), [Ubuntu images](https://www.alibabacloud.com/help/en/ecs/ubuntu-image).
- A system-assigned public IPv4 address can use **pay-by-bandwidth** (configured outbound rate over time) or **pay-by-traffic** (actual outbound GB); inbound transfer is not billed under this ECS static-IP rule. ECS, disks, snapshots, and other products have separate charges. Actual Hong Kong prices, inventory, taxes, and applicable offers are checkout-specific. [ECS public bandwidth billing](https://www.alibabacloud.com/help/en/ecs/public-bandwidth), [ECS billing overview](https://www.alibabacloud.com/help/en/ecs/billing-overview).
- Use an explicit inbound security group: TCP **80 and 443** from `0.0.0.0/0` for the public site; TCP **22** only from the operator's current public IP when using direct SSH. Review defaults because Alibaba says a default security group can expose SSH 22 broadly. For **Workbench over SSH**, Alibaba instead requires access from its specified Workbench ranges (public `161.117.0.0/16`, private `100.104.0.0/16`), or use a supported password-free/session method; a current-IP-only rule will not necessarily permit Workbench. These are alternative access paths, so verify the chosen method before changing rules. [ECS security groups](https://www.alibabacloud.com/help/en/ecs/user-guide/start-using-security-groups), [Workbench connection](https://www.alibabacloud.com/help/en/ecs/user-guide/workbench-overview/), [Linux Workbench login](https://www.alibabacloud.com/help/en/ecs/user-guide/connect-to-a-linux-instance-by-using-a-password-or-key).
- Workbench's browser file manager can upload a **compressed project archive** to Linux (documented 1200 MB limit), then the user can extract it on the instance. The file manager requires a **Workbench terminal connection**; Alibaba says its Session Management connection does **not** support file transfers. Its instance-details upload path is another option with a smaller documented limit. Archive selection should exclude private `.env`, live SQLite files, `node_modules`, and other machine-local artifacts; create server secrets directly on the server. [Workbench upload](https://www.alibabacloud.com/help/en/ecs/user-guide/use-workbench-to-upload-a-file-to-a-linux-instance), [transfer-method comparison](https://www.alibabacloud.com/help/en/ecs/user-guide/choose-how-to-transfer-files).

## DNS, HTTPS, and Hong Kong filing boundary

- Register or control a domain first; registration and DNS resolution are separate from ECS. In the authoritative DNS zone, add an **A** record with the desired subdomain label (e.g. `coach`, not `coach.example.com` in the hostname field) pointing to the instance's **public IPv4**, then confirm public resolution. If an **AAAA** record exists, ensure it points to a reachable IPv6 endpoint or remove/correct it; Caddy's certificate validation checks A/AAAA. [Alibaba Cloud DNS A-record instructions](https://www.alibabacloud.com/help/en/dns/pubz-add-parsing-record), [Caddy automatic HTTPS](https://caddyserver.com/docs/automatic-https).
- Alibaba's direct-hosting ICP guidance says an ICP filing is required for a website hosted on a **Chinese-mainland** server and **not required for a host outside the Chinese mainland**. A Hong Kong ECS origin falls under the latter hosting rule. This does **not** settle other content, privacy, business, PSB, CDN/edge-region, or jurisdiction-specific obligations; Alibaba specifically calls out PSB filing for services to mainland users and distinct ICP requirements when mainland CDN/ESA points of presence are used. Do not describe Hong Kong hosting as legal immunity or guaranteed mainland reachability. [Alibaba ICP website scenarios](https://www.alibabacloud.com/help/en/icp-filing/basic-icp-service/product-overview/icp-filing-requirements-for-a-regular-website), [CDN region/ICP distinction](https://www.alibabacloud.com/help/en/cdn/user-guide/change-the-accelerated-region).
- Caddy automatically obtains and renews public TLS certificates when the configured domain resolves to the server, **80/443 TCP** reach Caddy externally, Caddy can bind/receive those ports, and its `/data` storage persists. If the first issuance fails, check wrong/stale A or stray AAAA, closed ECS security group/host firewall, Docker port mapping, another process using 80/443, and Caddy logs; DNS propagation may take time. The existing Compose file also publishes **443/UDP** for HTTP/3, which needs its own inbound rule only if that protocol is desired; ACME's standard HTTP/TLS-ALPN checks use TCP 80/443. [Caddy automatic HTTPS](https://caddyserver.com/docs/automatic-https).

## Docker and repository-specific pitfalls

- Docker's [Ubuntu installation guide](https://docs.docker.com/engine/install/ubuntu/) supports Ubuntu 24.04 LTS and prescribes Docker's signed `apt` repository, then `docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin`; verify with `sudo docker run hello-world` and `docker compose version`. Follow the live guide's keyring/repository steps rather than an old `apt install docker.io` shortcut.
- Docker-published ports are exposed on host interfaces by default and Docker warns they can bypass `ufw`/`firewalld`; keep **only Caddy** published in `compose.yaml`, use ECS security groups as the outer public boundary, and do not publish app port 3000 or SQLite. [Docker Ubuntu install/firewall note](https://docs.docker.com/engine/install/ubuntu/), [port publishing](https://docs.docker.com/engine/network/port-publishing/).
- `docker compose config` resolves/interpolates environment values and can print the API key from this repo's `environment:` block. Do not paste its full output into chat, tickets, guides, or shared logs; `docker compose config -q` validates quietly. The repo's SQLite data is in a **named volume** (`app-data`, default `goal-coach-data-v020`); preserve the same volume name across updates and avoid `docker compose down -v`, which removes declared named volumes. Back up before any volume/image migration. [Compose config](https://docs.docker.com/reference/cli/docker/compose/config/), [Compose down](https://docs.docker.com/reference/cli/docker/compose/down/).

# Goal Coach 使用手册

前提：已完成[安装配置](quickstart.zh-CN.md)，或收到运营者的HTTPS网址与私下邀请码。邀请码不要发在公开链接或截图中。

## 1. 新建一个可验证的目标

选择学习或轻工作类别。不要只写“变优秀”；尽量给出成果、完成标准、期限和时间。例如：

> 四周内学习TypeScript，每周4小时。交付能新增、完成、删除待办且刷新后保留数据的网页，并记录自测结果。

具体日期用你自己的实际截止日，不直接照抄演示文件里的历史日期。教练可能追问必要信息；回答后会出现契约草案。

## 2. 审阅契约与初次计划

先看成果、期限、每周分钟和假设，有误就改，正确再点击界面批准。聊天里说“同意”不会替代结构性确认按钮。

计划出现后逐项检查：到底做什么、怎样算完成、要多久、依赖什么、提交哪类证据。接受3–8项当前任务；这是当前规划窗口，不要求把人生所有步骤一次列完。审批前只是草案。

## 3. 从当前行动开始

点击“开始这个任务”，实际执行任务。做完后填写实际分钟数和要求的完成证据，再提交完成。操作后刷新仍应看到已保存状态。

文件证据只记录文件名、大小和类型，**不会上传或读取文件内容**。不要据此认为模型已经审查了你的文件。文字/答案/用户确认同样需要你真实填写。

## 4. 卡住时记录事实

用“我卡住了”或“报告阻碍”，选择关联任务与阻碍类型，例如任务过大、时间不足或缺少资料，再写具体事实。记录后请教练分析；反馈记录和模型分析是不同操作。

时间变少时记录可用时间变化，而不是仅要求“更努力”。教练应给最小下一步；建议本身不改变正式任务。

## 5. 审阅重规划

让教练根据已记录反馈提出调整。查看新增、修改、移除和执行重置说明，确认已完成证据没有被悄悄丢弃。可以拒绝草案；只有明确批准才切换计划版本。

任务太大时，理想的小步骤有自己可验收的产物，而且产物会进入后续交付。不应只把相同工作估时改小。

容量不足时不要反复让模型“再试一次”。可明确增加真实可用时间，或在界面审阅范围/期限与手动计划变更。应用不会自动延长契约或保证调了数字就一定可行。

## 6. 撤销与异常恢复

“撤销上一步”针对最近支持撤销的任务变化或反馈，不是无限回溯。撤回反馈留历史标记，但不再参与当前分析。候选过期时需刷新，不能跨过它去撤销更早记录。

若请求超时，不确定有没有保存：先刷新核对状态与已有草案/证据，再使用界面提供的恢复或重试。不要快速连点或手工改数据库。模型故障时，已有批准任务的手动操作和导出仍可用；断网的PWA只显示说明页。

## 7. 复盘、完成、导出

所有必要任务完成后请求复盘，核对模型是否准确引用实际证据与用时。复盘语言可能出错，尤其不能将“估时比实际大”自动理解为你提高了效率。保存反思后由你明确完成目标。

“设置与数据”可导出JSON备份或按界面要求清除自己的业务数据。导出含对话及反馈历史，是私密资料，不要上传GitHub。清除是破坏性操作，不等于退出账号。

## 8. 邀请版与手机

每位朋友使用独立邀请码注册，不能共用管理员账号。首次使用真实模型都要独立确认数据说明；撤回同意停止后续派发，已发送内容不可追回。

手机打开运营者HTTPS网址：Android系统浏览器查看安装菜单，iPhone Safari使用分享→添加到主屏。不同浏览器能力不同；添加主屏不代表可以离线访问私人任务，也不是应用商店原生App。

关于实际效果，先记录“是否在10分钟内找到可开始行动”“是否愿意第二天继续”“多少建议要手改”“完成证据与调用成本”，再判断产品是否有用。公开演示不等于真实用户成效承诺。
